Start with a GGUF model

KoboldCpp is the app that runs your model. A model is the downloaded set of weights that supplies its capabilities. For text generation, look for a supported model in GGUF format.

Model repositories often offer several files with names such as Q4_K_M or Q5_K_M. These are quantization variants: different balances of size and fidelity. A Q4 variant is a useful starting point when memory is limited. Higher-bit variants generally take more memory.

Read the model card for its intended tasks, license, prompt format, and requirements. GGUF describes a file format; a new architecture can still require a newer KoboldCpp release.

Will it fit on my computer?

Model file size is only part of the memory requirement. Leave room for the context/KV cache, runtime buffers, the operating system, and any extra vision, image, or audio models.

What you changeWhat happens
More model parametersUsually more model memory and compute. A 13B model is not a drop-in substitute for a 4B model on a small machine.
Higher-bit quantizationUsually larger weights and greater memory use, with less quantization loss.
Longer contextMore cache memory and more text to process. Start modestly and work upward.
More GPU layersMore work and model data on the GPU. VRAM is different from system RAM.
Additional media modelsMore disk space and memory. A whole starter pack has different needs from a single text model.

For a first run, compare the selected file’s size with available memory and leave substantial headroom. If loading fails, reduce context, reduce GPU layers, or choose a smaller model or quantization. Partial GPU offload can use both GPU memory and system RAM, but speed depends on hardware and settings.

A template’s stated VRAM target is a starting point, not a guaranteed fit. Context, other running apps, backend, and additional models all affect memory use.

Beyond text: use the right files

Vision: image understanding usually needs both a supported text model and its matching mmproj projector. Match the model family and size; unrelated projector files are not interchangeable.

Image generation: needs a supported image model and sometimes separate encoders or a VAE. These are different from text GGUF models. Supported image workflows can use other formats, so follow their templates.

Speech and music: Whisper handles speech recognition; TTS models handle speech output; music templates fetch the components for music generation.

A few file-selection rules

  • Get the quantization you chose, not every version of the model.
  • If it is split into numbered shards, keep all matching shards together and follow the repository’s loading instructions.
  • For a normal text-model download, expect model data files; you do not need to run an unrelated installer from a model repository.
  • Read the model’s license separately from KoboldCpp’s software license.
  • If you need to convert a model, the project links conversion and quantization tools. Beginners can start with an already-converted GGUF.
