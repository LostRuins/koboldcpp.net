Windows setup

  1. Open the latest GitHub release and download koboldcpp.exe.
  2. Run the file. The standard Windows build bundles its runtime dependencies.
  3. Choose a GGUF model or load a .kcppt template, check the hardware preset, and click Launch.

For alternative builds such as no-CUDA or older-PC variants, follow the descriptions on the release page. If Windows shows a warning, verify the source and filename before deciding whether to run the file.

.\koboldcpp.exe --help

Linux setup

Download koboldcpp-linux-x64 from the release assets. In a terminal opened in the download directory:

chmod +x koboldcpp-linux-x64
./koboldcpp-linux-x64

If the current x64 binary is incompatible with your CPU, check the koboldcpp-linux-x64-oldpc asset. ARM Linux systems may need to build from source; the x64 binary is not an ARM build.

macOS setup

On an Apple Silicon Mac, download koboldcpp-mac-arm64 and run these commands in its directory:

chmod +x koboldcpp-mac-arm64
./koboldcpp-mac-arm64

If macOS blocks the app, verify that it came from the official release and review the app-specific approval in Privacy & Security. Older Intel Macs should follow the project’s source-build instructions.

Other ways to run

Android: build through Termux with the instructions in the README. Small models are a better starting point on memory-limited devices.

Source builds: available for additional systems and custom backends. See the README for compiler and platform-specific dependencies.

Cloud: the official Colab notebook and RunPod templates offer remote GPU options. Usage limits, availability, and charges depend on the provider.

Docker: intended primarily for experienced users and cloud GPU environments. Start with a native binary for a straightforward desktop setup.

Updates & mirrors

Check the release notes before replacing your executable. Keep your model files and saved stories; you do not normally need to download models again for an app update.

The SourceForge mirror is an alternative when GitHub is unavailable. Compare its version with the official GitHub release, since mirrors can lag. The release page remains the reference for current build names and compatibility.
